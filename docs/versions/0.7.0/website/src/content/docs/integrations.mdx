Innov detects supported agents automatically. Official integrations can add native session identity for restore, lifecycle state reports, or both.

Use integrations when you want native agent session restore from Claude Code/Codex/Copilot/Devin-style hooks, direct lifecycle reports from Pi/OMP/Kimi/OpenCode/Kilo/Hermes-style hooks or plugins, or both. See [Agents](/docs/agents/) for the full status authority model.

## Install integrations

Open settings inside Innov and use the integrations tab to install recommended integrations for agents found on your `PATH`, or run commands manually:

```bash
innov integration install pi
innov integration install omp
innov integration install claude
innov integration install codex
innov integration install copilot
innov integration install devin
innov integration install droid
innov integration install kimi
innov integration install opencode
innov integration install kilo
innov integration install hermes
innov integration install qodercli
innov integration install cursor
```

## How Innov uses integrations

Innov uses integrations in two different ways:

| Integration type | Agents | Effect |
| --- | --- | --- |
| Lifecycle authority | Pi, OMP, Kimi Code CLI, OpenCode, Kilo Code CLI, Hermes Agent | When installed and actively reporting for the pane, hook or plugin events author `idle`, `working`, and `blocked`. Innov does not also use screen manifest fallback for that same lifecycle authority. |
| Session identity | Claude Code, Codex, GitHub Copilot CLI, Devin CLI, Droid, Qoder CLI, Cursor Agent CLI | The integration reports native session references for restore. State still comes from Innov's screen manifest detection. |

Custom socket integrations can also report state when they define state that is not visible in the native terminal UI.

Some integrations report native agent session references. Innov uses official session references to resume Claude Code, Codex, Devin CLI, Droid, Kimi Code CLI, Qoder CLI, Cursor Agent CLI, GitHub Copilot CLI, Pi, Hermes Agent, OpenCode, and Kilo Code CLI panes after a Innov server restart unless `[session] resume_agents_on_restore = false` disables it.

Native session restore requires current Innov integrations: Pi integration version `2`, Claude Code version `6`, Codex version `5`, GitHub Copilot CLI version `2`, Devin CLI version `1`, Droid version `2`, Kimi Code CLI version `3`, Qoder CLI version `2`, Cursor Agent CLI version `1`, OpenCode version `5`, Kilo Code CLI version `1`, or Hermes Agent version `2`. OMP integration version `2` reports agent state only. Check installed versions with `innov integration status`.

## Pi

Install the Pi integration:

```bash
innov integration install pi
```

Innov writes the bundled extension to:

```text
~/.pi/agent/extensions/innov-agent-state.ts
```

If `PI_CODING_AGENT_DIR` is set, Innov writes to `$PI_CODING_AGENT_DIR/extensions/innov-agent-state.ts` instead. The extensions directory must already exist. Uninstall removes only that extension file.

## OMP

Install the OMP integration:

```bash
innov integration install omp
```

Innov writes the bundled extension to:

```text
~/.omp/agent/extensions/innov-omp-agent-state.ts
```

If `PI_CODING_AGENT_DIR` is set, Innov writes to `$PI_CODING_AGENT_DIR/extensions/innov-omp-agent-state.ts` instead. The extensions directory must already exist. Uninstall removes only that extension file.

The OMP integration reports `omp` as the agent label through Innov's socket API. It does not require native process detection for the `omp` executable.

## Claude Code

Install the Claude Code hook:

```bash
innov integration install claude
```

The hook reports Claude Code session identity to the local Innov socket on session start. Claude Code state comes from Innov's screen manifest detection.

Innov uses `~/.claude` by default, or `CLAUDE_CONFIG_DIR` when set. The Claude config directory must already exist. Install writes `hooks/innov-agent-state.sh` and updates `settings.json` with Innov hook entries. Uninstall removes the matching hook entries and deletes the hook script.

## Codex

Install the Codex hook:

```bash
innov integration install codex
```

The Codex hook reports session identity through the same local socket API used by other integrations. Codex state comes from Innov's screen manifest detection.

Innov uses `~/.codex` by default, or `CODEX_HOME` when set. The Codex config directory must already exist. Install writes `innov-agent-state.sh`, updates `hooks.json`, and ensures `[features] hooks = true` in `config.toml`. It also removes the deprecated top-level `codex_hooks` flag when present. Uninstall removes Innov entries from `hooks.json` and deletes the hook script, but leaves `config.toml` unchanged.

## GitHub Copilot CLI

Install the GitHub Copilot CLI hook:

```bash
innov integration install copilot
```

The Copilot hook reports session identity through the same local socket API used by other integrations. Copilot state comes from Innov's screen manifest detection.

Innov uses `~/.copilot` by default, or `COPILOT_HOME` when set. The Copilot config directory must already exist. Install writes `hooks/innov-agent-state.sh` and updates `settings.json` with a `SessionStart` hook entry. Uninstall removes Innov entries from `settings.json` and deletes the hook script.

After Copilot emits a session-bearing event, Innov can use the reported session id to resume the pane with `copilot --resume=<id>`.

## Devin CLI

Install the Devin CLI hook:

```bash
innov integration install devin
```

The hook reports native session identity from Devin session, prompt, tool-use, permission, and stop events. Devin state still comes from Innov's screen manifest and OSC detection because Devin hooks do not emit a reliable state transition after every permission cancellation or user interrupt.

Innov uses `~/.config/devin` by default, or `$XDG_CONFIG_HOME/devin` when `XDG_CONFIG_HOME` is set. The Devin config directory must already exist. Install writes `innov-agent-state.sh` and updates `config.json` with Innov hook entries. The hook refreshes the session reference while Devin runs. Uninstall removes Innov entries from `config.json` and deletes the hook script.

Innov resumes stored Devin sessions with `devin --resume <id>`. Native screen manifest detection remains the state authority whether or not the hook is installed.

## Kimi Code CLI

Install the Kimi Code CLI hook:

```bash
innov integration install kimi
```

The hook reports Kimi session identity and lifecycle state to Innov for native restore and authoritative `idle`, `working`, and `blocked` status. It requires Kimi Code CLI `0.14.0` or newer.

Innov uses `~/.kimi-code` by default, or `KIMI_CODE_HOME` when set. The Kimi Code config directory must already exist. Install writes `hooks/innov-agent-state.sh` and appends Innov-managed `[[hooks]]` entries to `config.toml`. Uninstall removes the Innov-managed config block and deletes the hook script.

Innov resumes stored Kimi sessions with `kimi --session <id>`.

## Droid

Install the Droid hook:

```bash
innov integration install droid
```

The Droid hook reports session identity through the same local socket API used by other integrations. Lifecycle state still comes from Innov's screen manifest detection because Droid hooks do not cover every lifecycle transition.

Innov uses `~/.factory` for Droid hooks. The Factory config directory must already exist. Install writes `hooks/innov-agent-state.sh`, updates `settings.json` with a Innov `SessionStart` hook entry, and removes older Innov Droid hook entries from `hooks.json` if present. Uninstall removes Innov entries from both config files and deletes the hook script.

After Droid emits a session start event, Innov can use the reported session id to resume the pane with `droid --resume <id>`.

## Hermes Agent

Install the Hermes Agent plugin:

```bash
innov integration install hermes
```

Innov writes `~/.hermes/plugins/innov-agent-state/` and enables `innov-agent-state` in `~/.hermes/config.yaml`. The Hermes config directory must already exist. Restart Hermes after installing so the plugin loads. Uninstall removes the plugin directory and removes `innov-agent-state` from `plugins.enabled`.

The plugin reports lifecycle, tool, approval state, and session id while Hermes runs inside a Innov pane. Innov can use the reported session id to resume the pane with `hermes --resume <id>`. Native screen manifest detection remains available when the plugin is not installed.

## Cursor Agent CLI

Install the Cursor Agent CLI hook:

```bash
innov integration install cursor
```

The hook reports session identity through Cursor's `sessionStart` hook while Cursor Agent CLI runs inside a Innov pane. Cursor state comes from Innov's screen manifest detection.

Innov uses `~/.cursor` by default, or `CURSOR_CONFIG_DIR` when set. The Cursor config directory must already exist. Install writes `innov-agent-state.sh` and adds a Innov `sessionStart` entry to `hooks.json`. Uninstall removes the matching hook entry and deletes the hook script.

After Cursor emits a session start event, Innov can use the reported session id to resume the pane with `cursor-agent --resume <id>`. The `cursor-agent` command must be on `PATH` when Innov restores the pane; Innov does not launch the generic `agent` command.

## Custom status labels

Integrations can report a short visual label without changing the semantic state.

For example, an agent can remain semantically `working` while showing `indexing` in the UI.

```bash
innov pane report-agent w1:p1 \
  --source custom:docs \
  --agent docs-bot \
  --state working \
  --custom-status indexing
```

User hooks that run next to a Innov-managed integration should use metadata instead of `report-agent`. Metadata changes presentation without taking over the integration's `idle`, `working`, `blocked`, or session restore authority. `--agent` guards the report so it only applies while that authoritative agent is active. `--applies-to-source` guards the report so it only applies while that lifecycle authority source is active. `--display-agent` changes the visible name.

```bash
innov pane report-metadata "$INNOV_PANE_ID" \
  --source user:claude-title \
  --agent claude \
  --title "Refactor auth middleware" \
  --display-agent "Claude: auth" \
  --custom-status "refactor auth" \
  --state-label working="refactoring auth" \
  --ttl-ms 3600000
```

Custom status and state labels are visual-only. Waits, notifications, and workspace rollups still use the semantic state.

## Debug integration state

List known agents:

```bash
innov agent list
```

Read a pane when you need to verify what Innov can see:

```bash
innov pane read w1:p1 --source recent --lines 50
```

If integration state looks wrong, first confirm the agent is running inside Innov and that the relevant hook or plugin was installed for the same user account.
